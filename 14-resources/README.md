# Resources

Curate resources; do not make this a raw link dump. Record title, publisher / author, URL, topic, date accessed, version relevance and why the resource is useful.

Prefer official documentation for product behaviour. Community discussions and interview experiences are useful context, not guarantees about company hiring or interview content.

## Selection and review rules

- Official documentation is the authority for current product behaviour.
- Community repositories are supplementary; verify commands, versions and maintenance state.
- Interview experiences are anecdotal and do not predict a particular hiring loop.
- Review cloud cost, permissions, cleanup and security before running any lab.
- Record the date accessed when adding or materially updating a resource.
