# Contribution Guide

This is primarily a personal engineering handbook. Public corrections and useful contributions are welcome.

## Standards
- Be technically precise and respectful.
- Prefer official documentation and reproducible evidence.
- State versions, operating systems and prerequisites when they affect behaviour.
- Never include secrets, credentials, private keys or confidential employer material.
- Do not reproduce copyrighted articles, paid course material or private interview content.
- Clearly label unverified assumptions.

## Workflow
1. Open an issue describing the correction or addition.
2. Keep changes focused on one topic.
3. Include sources and test evidence.
4. Explain limitations and version assumptions.
5. Submit a pull request with a concise summary.

## Review checklist
- [ ] Explanation is original and technically clear.
- [ ] Commands and configuration are safe and reproducible.
- [ ] Expected output and failure modes are described.
- [ ] Sources are linked and access dates recorded.
- [ ] Secrets and private data are absent.
- [ ] Interview answers show reasoning, not copied wording.
