## Interview answer framework

For technical questions:
1. Define the concept and the problem it solves.
2. Explain the mechanism or request/data flow.
3. Give a practical command, configuration or example.
4. Describe a common failure and evidence-led diagnosis.
5. Explain security, reliability and cost trade-offs.
6. State limits of your own experience accurately.

For scenarios: clarify impact and constraints, gather evidence, prioritize mitigation, isolate root cause, implement the smallest safe change, verify recovery and describe prevention.

## Daily practice protocol

- Pick 10–15 questions from one domain.
- Answer aloud before reading reference material.
- Mark each answer correct, incomplete, incorrect or unknown.
- Turn weak answers into a practical lab.
- Re-test weak questions after 24–72 hours.
- Record the source URL and date for company-specific experiences.
- Do not treat anecdotal candidate reports as guaranteed questions.

## Company-specific preparation

Create a company note only when there is a real target application or interview. Record role, location, job description URL, report date, candidate experience level if stated, rounds, topic clusters, confidence and gaps. Do not republish private interview material or claim that reported questions are official.

## Readiness score

A question is interview-ready only when you can answer clearly without notes, handle a follow-up, and connect the concept to practical evidence. Question count alone is not mastery.
