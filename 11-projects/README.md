# Projects

Projects demonstrate implemented and tested engineering. Distinguish implemented, simulated, planned and unverified functionality.

- [AWS Infrastructure Auditor](aws-infrastructure-auditor/README.md)
- [Ops Sentinel](ops-sentinel/README.md)
- [AWS Emulator Lab](aws-emulator-lab/README.md)
- [Kubernetes Agents](kubernetes-agents/README.md)

For each project document problem, scope, architecture, data flow, threat model, permissions, setup, tests, evaluation, sanitized demo, costs, cleanup and limitations. Do not claim production readiness unless deployment, security, reliability and operational controls have been verified.

See the [Project Readiness tracker](../PROJECT-READINESS.md) for current evidence gaps and a portfolio completion checklist.

## External project references

- [DevOps Projects](https://github.com/NotHarshhaa/DevOps-Projects) — choose one guided project at a time and independently review its scripts and cloud footprint.
- [Cloud Projects](https://github.com/mzazon/cloud-projects) — use selected CLI recipes to study service combinations, IaC alternatives and cleanup patterns.
- [Google Online Boutique](https://github.com/GoogleCloudPlatform/microservices-demo) — optional multi-service Kubernetes study application.
- [DevOps AI Playbook](https://github.com/vishakhasadhwani/devops-ai-playbook) — architecture reference for an integrated DevOps and AIOps project.

External projects are references, not evidence of work completed by this handbook's author. Record your own fork, commits, test results and deployment environment before claiming implementation.
