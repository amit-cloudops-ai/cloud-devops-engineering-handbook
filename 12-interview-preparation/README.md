## Question depth

1. Foundational — define and explain.
2. Mechanistic — explain how it works.
3. Practical — demonstrate commands or configuration.
4. Troubleshooting — diagnose from evidence.
5. Design — choose an approach and defend trade-offs.

Answer aloud without reading. State assumptions, ask clarifying questions when needed, and be honest about what you have not used or verified in production.

## Daily practice protocol

- Pick one core topic and 10–15 questions, not an entire repository.
- Answer aloud before reading reference material.
- Mark each answer: correct, incomplete, incorrect or unknown.
- For incomplete/incorrect answers, write a short explanation and perform a related lab.
- Re-test weak questions after 24–72 hours.
- Add source URL and date accessed to company-specific notes.
- Never represent an anecdotal interview report as a guaranteed company question.

## Company-specific preparation

Maintain one file per company only when there is a real target application or interview. Record role, location, job description URL, reported interview date, candidate experience level if stated, rounds, topic clusters, confidence and gaps. Do not scrape, republish or present private interview material as official company content.

## Readiness standard

A question is interview-ready only when you can answer clearly without notes, handle at least one follow-up, and connect the concept to practical evidence. A high number of checked questions is not a substitute for engineering competence.
