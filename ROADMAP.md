# Accelerated Competency Roadmap

This roadmap is competency-based. It deliberately does **not** allocate one week to every topic. The target is faster progression through shared foundations while maintaining applications and interview practice in parallel.

## Priority model

- **P0:** essential screening and day-to-day engineering foundations.
- **P1:** common role differentiators and production competence.
- **P2:** specialization or role-dependent breadth.

## Execution sequence

| Sequence | Focus | Completion gate |
|---:|---|---|
| 1 | Linux, OS and networking | Diagnose host and request-path failures; explain commands and evidence |
| 2 | Git, Bash and Python | Complete tested automation and safe collaboration workflows |
| 3 | AWS fundamentals | Explain IAM, VPC, EC2, S3, routing, monitoring and cost |
| 4 | Docker and Compose | Build and troubleshoot multi-container workloads |
| 5 | CI/CD and release engineering | Pipeline tests, artifacts, scans, approvals and rollback |
| 6 | Kubernetes | Deploy and diagnose workloads, services, storage and networking |
| 7 | Terraform and IaC | Understand plan, state, modules, drift and safe review |
| 8 | Observability and SRE | Investigate incidents using metrics, logs, traces and SLOs |
| 9 | Security and FinOps | Apply least privilege, supply-chain controls and cost analysis |
| 10 | AI infrastructure and MLOps | Explain and measure inference, GPU, RAG and model lifecycle |
| 11 | Agentic AI and AIOps | Build bounded read-only agents with evaluations and approval boundaries |
| 12 | System design and interview sprint | Defend designs, explain projects and handle production scenarios |

## Fast-track operating rhythm

Use a repeatable learning cycle rather than fixed calendar blocks:

1. **Concept pass:** one focused explanation and official documentation.
2. **Build pass:** a lab or project change that demonstrates the concept.
3. **Failure pass:** introduce a safe failure and diagnose it from evidence.
4. **Recall pass:** answer interview questions without notes.
5. **Evidence pass:** document results and update the dashboard.

A small topic can move through this cycle in one session. A complex topic can take several sessions. Do not advance merely because a timebox expired.

## First 30-day framework

This is a priority framework, not a fixed timetable. Compress or expand based on demonstrated competence; job applications run in parallel from the start.

### Sprint A — Baseline and foundations
- Audit Linux, networking, Git, Bash and Python.
- Complete LAB-LNX-01 and LAB-NET-01.
- Answer the first 40 questions in the interview bank selectively.
- Repair project READMEs and prepare a concise walkthrough for each credible project.

### Sprint B — Cloud and containers
- Review IAM, VPC, EC2, S3, CloudWatch, DNS and cost drivers.
- Use the AWS emulator or static policy analysis before any real cloud provisioning.
- Complete LAB-DOCKER-01 and a safe AWS policy lab.
- Explain one architecture end to end.

### Sprint C — Delivery and orchestration
- Build a CI pipeline with tests, scans and artifacts.
- Practise Kubernetes with kind or a hosted lab.
- Learn Terraform plan/state/module workflows using local validation and plan review.
- Complete at least three Kubernetes troubleshooting scenarios.

### Sprint D — Reliability, security and AI
- Create a dashboard and actionable alert from sample telemetry.
- Analyse one primary-source postmortem.
- Run a local model and measure latency, tokens/sec and resource usage.
- Build a read-only operations agent and test prompt-injection/unsafe-tool cases.

### Sprint E — Interview and application execution
- Run mixed-topic mock interviews.
- Practise project walkthroughs and system design.
- Match skills to actual job descriptions and target companies.
- Track applications, outreach, referrals and follow-ups.

## Parallel job-search routine

Do not wait for the end of a curriculum before applying. For each relevant role:
- Save the job description and identify must-have vs preferred skills.
- Map requirements to evidence in your projects and handbook.
- Tailor the resume honestly; never claim tools or production experience not demonstrated.
- Find relevant engineers/recruiters and send thoughtful, role-specific outreach.
- Record application date, contact, follow-up and interview feedback.

## Interview readiness gate

A skill is interview-ready only when you can:
- Define it and explain why it exists.
- Describe its architecture or execution flow.
- Use relevant commands or tooling.
- Diagnose at least one common failure.
- Explain security, reliability and cost implications where relevant.
- Answer foundational, practical and scenario-based questions in your own words.

## Weekly review

- What can I explain without notes?
- What have I implemented and verified?
- What failed, and how did I diagnose it?
- Which interview questions are still weak?
- Which job descriptions reveal a meaningful skill gap?
- What low-priority study should I stop doing?
